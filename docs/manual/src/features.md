# Features and their tests

Everything the amp-model plugin does, and the tests that check it. The test names are the ones `cargo test` prints. `scripts/test-all.py` fails when a feature here names no test, or names a test that doesn't exist, so a new feature gets its row and its tests in the same pull request (the [Testing](testing.md) page says how to run them).

| Feature | What it does | Tests |
| --- | --- | --- |
| Amp models on a track | A `.nam` model plays a track through an amp, in pieces of any size, as NeuralAmpModeler-rs (or nam-rs) computes it. | `engine::tests::models_play_whatever_the_pieces_are`, `engine::tests::the_facts_are_nam_rs_s`, `host::our_nam_plugin_runs_a_model_in_real_time` |
| Two builds, one sound | A second file for x86_64 processors with AVX2 and FMA, which OxiGuitar picks where the processor has them; the two manifests differ only in that. | `host::the_nam_build_for_x86_64_v3_processors_runs_in_real_time_and_is_chosen`, `tests::the_two_manifests_differ_only_in_their_conditions` |
| Models at their own rate | Models run at 48 kHz; on a device at another rate the track goes there and back, whole and at its level, late only by the latency OxiGuitar makes up for. | `resample::tests::a_whole_signal_keeps_its_pitch_and_level`, `resample::tests::a_stream_there_and_back_comes_back_whole_and_late_by_its_latency`, `host::our_nam_plugin_converts_the_rate_for_its_model` |
| Cabinets | Four built-in impulse responses, or any `.wav` of the user's; read as nam-rs reads them, brought to one level, convolved with no latency. | `wav::tests::the_shipped_responses_read`, `wav::tests::the_first_channel_of_each_format`, `wav::tests::damage_is_refused_with_a_sentence`, `engine::tests::a_cabinet_is_read_as_nam_rs_reads_it`, `convolve::tests::responses_are_brought_to_one_level`, `convolve::tests::it_matches_the_plain_sum_with_no_latency_in_pieces_of_any_size`, `convolve::tests::a_short_response_needs_no_partitions` |
| Input and Output | Drive and level from -24 to +24 dB, followed while the song plays and gliding there; another model or cabinet waits for the next start. | `tests::levels_follow_and_files_wait`, `tests::a_level_glides`, `settings::tests::wrong_values_keep_their_defaults` |
| The nam folder | Models and responses found in the nam folder and four folders below it; a name that would leave the folder is refused. | `files::tests::models_and_responses_are_found_inside_folders`, `files::tests::folders_are_looked_into_five_deep_and_no_deeper`, `files::tests::names_leaving_the_folder_are_refused` |
| Says what the folder lacks | No model, or no cabinet of the user's (unless the model has its own), is advised with a link to this manual. | `advice::what_the_nam_folder_lacks_is_advised` |
| The Amp section of the Track tab | On or off, model and cabinet pickers, input and output levels, the folder and a link to the manual; a missing model stays shown; the clean-guitar hint shows while the amp is on. Drawn by `ui/nam.slint`, which compiles with what the plugin sets and hears; the link opens only `https://` addresses. | `section::tests::a_missing_model_stays_shown_and_none_comes_first`, `section::tests::the_clean_guitar_hint_shows_while_the_amp_is_on`, `section::tests::the_section_picks_the_model_the_cabinet_and_the_levels`, `section::tests::the_slint_file_has_what_the_section_sets_and_hears`, `links::tests::only_web_addresses_are_opened` |
| Saved with the track | Settings round trip and keep keys this version doesn't know; wrong values keep their defaults. | `settings::tests::settings_round_trip_and_keep_unknown_keys`, `settings::tests::wrong_values_keep_their_defaults` |
| A working plugin file | The `.oxp` file loads in OxiGuitar's host and plays in real time, and keeps the plugin contract with the newest release of OxiGuitar. | `host::our_nam_plugin_runs_a_model_in_real_time`, `oxiguitar_plugin_checks::the_manifest_matches_the_plugin`, `stage:contract (latest core)` |
